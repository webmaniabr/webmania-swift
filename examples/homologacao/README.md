# Exemplo de homologação

[examples/homologacao](.) is an optional walk-through of reads, the NF-e lifecycle and the NFS-e lifecycle in homologation (`ambiente` 2): issue, consult, files, cancel and final consult. It sends nothing unless `WEBMANIA_LIVE=1`; otherwise it prints `{"result":"blocked"}` and exits with 77. Base URLs, credentials and payloads come only from the environment (`WEBMANIA_API1_BASE_URL`, `WEBMANIA_FILES_BASE_URL`, `WEBMANIA_API2_BASE_URL`, `WEBMANIA_CONSUMER_KEY`, `WEBMANIA_CONSUMER_SECRET`, `WEBMANIA_ACCESS_TOKEN`, `WEBMANIA_ACCESS_TOKEN_SECRET`, `WEBMANIA_ISSUER_TOKEN`, `WEBMANIA_LIVE_SCOPE`, `WEBMANIA_LIVE_NFE_PAYLOAD`, `WEBMANIA_LIVE_NFSE_PAYLOAD`, `WEBMANIA_LIVE_LEDGER`, `WEBMANIA_LIVE_ALLOWED_HOSTS`). `WEBMANIA_LIVE_ALLOWED_HOSTS` is required (comma-separated hosts that include the host of every base URL); without it the example exits with 77 before reading credentials or sending a request. The top-level `ambiente` of each payload must be exactly the JSON integer 2 (the text `"2"`, `2.0` or `2e0` is refused). Standard output has one JSON line per step without identifiers, payload values or credentials; a mutation is never resent and an unknown outcome exits with 1. After the issue the document is consulted until a terminal status, and it is cancelled only when a consult shows it `aprovado`, whether the issue call approved it or it was approved later; a refused document gets no other mutation, and one without a terminal status within the bound is ledgered as `unknown` for reconciliation (the issue is never resent). In both cases the example exits with 1. The ledger at `WEBMANIA_LIVE_LEDGER` must be writable before the first mutation and keeps the document identifiers for reconciliation: keep it private.

```sh
WEBMANIA_LIVE=1 WEBMANIA_LIVE_SCOPE=readonly sh examples/homologacao/run.sh
```
